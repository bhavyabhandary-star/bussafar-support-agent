## How to re-run

From the project root, with `GOOGLE_API_KEY` (and `APP_PASSCODE`) in `.env`:

```bash
pip install -r requirements.txt
python -m pytest -q                      # unit + UI tests (offline, no API calls)
RUN_LIVE_TESTS=1 python -m pytest -q tests/test_live_agent.py   # live Gemini checks (optional)
python tests/qa/run_qa.py                # full QA plan, live Gemini, paced at 12 calls/min
python tests/qa/run_qa.py --only POL,DEL # re-run some modules (rewrites the report with only those rows)
python tests/qa/run_qa.py --offline      # no API calls; model-dependent cases show Blocked
```

A full live run makes about 90 Gemini calls (roughly 10 minutes on the free tier; the free daily quota is about 500). Test data is the 12 fictional bookings in `data/bookings.csv`; phone digits are shown as `****` in every report. UI-014 (mobile) is checked with headless Chromium at 375×812 and read from `tests/qa/ui_mobile_result.json`.

## Clarifications (current behaviour, not new policy)

- **Refund processing timeline when a bus is more than 3 hours late:** The help docs only say the traveller can cancel for a full refund. Sahil quotes that and does not state a processing time for this case. It does not borrow the 5 to 7 working day or 3 working day timelines unless the customer asks about refunds generally.
- **Support ticket SLA and human-support contact mechanism:** Not in the help docs. Following the project brief, Sahil says 'A person from our support team will reply within 24 hours' after creating a ticket. Tickets are saved to tickets.csv (reset on restart when hosted). No phone number or email is given.
- **Is the ₹2,000 rule the requested refund or the booking amount?:** Implemented as the requested refund amount named in the message (₹/Rs/INR/rupees). Above ₹2,000 creates a refund_dispute ticket in code. Exactly ₹2,000 does not escalate on amount alone (POL-010). The booking amount is not used, and none of the 12 bookings exceeds ₹2,000.
- **Date change when no seats are available:** Not in the help docs. Sahil states the documented rule (once, up to 24 hours before departure, ₹100 plus fare difference) and does not invent an availability rule. If pressed, it gives the fallback and offers a person.
- **ESC-010 duplicate escalation:** Hand-offs enforced in code (lost item, bus no-show or left early, person requested, refund above ₹2,000, safety) create one ticket per issue type per chat. Repeating the request returns the original ticket ID and says no new ticket was created.
